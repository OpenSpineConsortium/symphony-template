## What was learned

- A board release renames the branch, and GitHub then leaves the claim's draft open against a head that is gone, rather than closing it as PROTOCOL.md's Release section expects. Such drafts pile up on the pull request lists; a later pass closes them, the work staying on the released branch. Whether GitHub's behaviour changed or the rename path differs is not checked.
- A pull request opened before a newly required check existed stays blocked with every check green until a new pull_request event runs that check; update-branch is the lightest such event.
- spine-program #225 holds the two CNS 2026 talks (707 files) on released/224-97feeab, and issue #224 is back in the queue; with the talk on 2 November it wants claiming again soon, carrying that branch on.
- The thread's auto-mode check refused closing pull requests in bulk until the owner had seen the list and chosen on a card.
