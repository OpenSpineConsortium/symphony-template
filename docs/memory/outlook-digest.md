The Outlook digest: progress and decisions as an Outlook actionable message answered inside Outlook, tools/outlook_digest.py, and why Wayne State's Files consent covers no mail.

Buttons inside an email are an Adaptive Card 1.0 with Action.Http (Outlook drops Action.Submit); a self-sent card renders unregistered, any other needs a provider at https://aka.ms/ActionableMessagesPortal (Test Users scope approves itself) and a signed card; every press carries a Microsoft JWT (iss https://substrate.office.com/sts/, aud the endpoint's host, sub the presser) the endpoint checks. SymphonyBoard Folders' consent is Files.ReadWrite and offline_access only, so Mail.Send or Mail.Read would need Wayne State again; the owner chose on 2026-10-20 the Microsoft 365 native route, self-sent from the owner's Wayne State mailbox through Graph, which waits for C&IT's consent to Mail.Send and Mail.Read on a separate Entra app (docs/research/microsoft-365-permissions.md has the phased request); sending from Symphony's own address is the fallback. A decision is an issue labelled decision with an "## Options" section; tools/outlook_digest.py composes the digest, and plans what a button or a reply asks for, sending nothing. docs/research/outlook-digest.md has the design and what waits on the owner. Since 2026-10-20 the digest runs natively on GitHub instead (the owner's choice): .github/workflows/digest.yml and tools/github_digest.py comment it on an issue labelled digest that mentions the recipient, GitHub emails it, and a reply to that email, posted back as a comment, is answered by line ("12 Accept"), with no Graph permission and no secret.
