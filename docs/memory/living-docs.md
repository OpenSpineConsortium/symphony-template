The lessons and their Colab notebooks live in the public symphony-protocol, under lessons/ and notebooks/, and the template carries no copy; the template's living docs are the site, the reference and the tests.

On 2026-10-20 the owner chose to move the lessons into symphony-protocol rather than keep a copy here and export it (the bespoke export pipeline of symphony-template#292 was closed unmerged, and the owner is leaving GitHub Enterprise, so internal visibility goes too). There scripts/lessons.py runs every block marked `bash run` in a fresh practice folder and fails when the `output` block after it is no longer printed, and makes each lesson's notebook, which its check holds to the lesson; scripts/run_notebook.py and its notebooks.yml run the notebooks as Colab does, weekly. A lesson changes by pull request in symphony-protocol, never here; docs/learn/README.md here only links them. A board snapshot in a lesson carries claimed issues' labels in `claim_issues` as well as `issues`: the board reads a claim's blocker label only from there.

Here, tools/living_docs.py `check` fails when a module under tools/ or scripts/ has no docstring or a shell script no opening comment, since the site's Reference page is made from them. A lease written in any page names its ref and tip (`--force-with-lease=claude/N:<tip>`), which tests/test_claim_skill.py enforces. .github/workflows/docs.yml builds the site on each push to the default branch and deploys it with Pages where Pages deploys from GitHub Actions (read with the token's pages: read) and the variable SYMPHONY_DOCS is pages, so a site published another way is never overwritten; scripts/setup-repo.sh sets both, since the token cannot, and limits a non-public repository's site to its readers or makes none; on 2026-10-20 the owner chose members-only Pages on symphony-template for now.
