The required check runs as parts side by side: ci.yml's job parts runs scripts/check.sh without its tests and the tests cut into four, and the job check waits for them all.

tools/test_shard.py cuts the modules unittest's discovery finds (tests/test*.py) into parts, longest first, by the seconds tests/durations.json records; a module the file does not name counts as one second, so a stale file only makes the parts uneven, never leaves a test out. When a test module grows much slower or a new slow one lands, run `python3 tools/test_shard.py measure` and commit the rewritten tests/durations.json. Locally, `bash scripts/check.sh` still runs every test; CI sets CHECK_TESTS=none for its part "rest" so the tests run once. A test that reads ci.yml's shape finds the checks in the job parts and the crowd guard and protocol check in the job check (tests/test_crowd_check.py). The research is docs/research/faster-backend-than-actions.md, section 7.
