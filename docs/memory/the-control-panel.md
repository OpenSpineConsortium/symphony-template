The control panel is two pages of the site, /symphony/control/ to drive a Symphony repository through GitHub's API as the signed-in person and /symphony/cost.html to price the work against the other ways of running coding agents on GitHub; neither ever holds a Claude token.

# The control panel

- Where: OpenSpineConsortium/openspineconsortium.github.io, the body files tools/pages/symphony/control/index/body.html and tools/pages/symphony/cost/body.html, one script assets/js/symphony-panel.js and assets/css/control.css, built by tools/build_site.py like every page; the panel is out of the navigation (hidden=True) and linked from /symphony/, the cost page is in it. Plain HTML and JavaScript, no dependency, no server of ours: the page calls api.github.com as the person.
- What it drives: adds a repository (one whose About carries the topic symphony joins the list; another gets the two presses, the App's install link preselected for it and the form); shows the board (STATE.md on the branch board), the queue, the issues given to workers, claimed, in review, blocked and the epics; queues a task as an issue labelled todo in the Task form's shape; asks Claude with an issue or a comment that mentions @claude, which claude.yml answers; registers a worker as an "Add a worker" issue in the form's shape, which add-worker.yml turns into the pull request; lists the pull requests with their checks and merges a ready one whose checks are green; starts the workers, the board, the checks and the metrics by workflow_dispatch. Every state is in words under the summary line and every button is named, so a Claude driving a browser reads and presses it like a person; ?repo=OWNER/NAME opens a repository.
- Sign-in: "Sign in with GitHub" first, as the owner asked on 2026-10-16 (one-click sign-in as the primary option, as opposed to a fine-grained token): the SymphonyBoard App's user token through the stateless sign-in service symphony-app/signin (a Cloudflare Worker that holds the App's client secret, exchanges the code with PKCE, refreshes, revokes, keeps nothing). The button is the first thing on both pages and can be pressed once the script's SIGNIN_SERVICE and CLIENT_ID are set, which waits on the owner deploying the Worker and sending a session its address and the Client ID (neither a secret); until then one line says why and the token box stands open. The fallback, folded under "Use a fine-grained token instead", is a fine-grained personal access token the person pastes. Either is kept in the browser only (localStorage with "Keep me signed in", else sessionStorage, where a sign-in for one tab keeps its refresh token in the page's memory alone, so it ends with its eight-hour token once its page is gone, closed, reloaded or left for another page); a pasted token is asked about at GitHub before it replaces anything; the tabs renew a sign-in in turn, only GitHub's bad_refresh_token ends one, a tab whose own sign-in ended takes up no other, and Forget the token signs out at once every tab that used the kept one and ends a renewal waiting its turn; a call goes out only with a token GitHub has named for the page, and a write only for the account the page named when it was asked for. The workers themselves run on the repository's own secret; the panel never asks for one.
- The cost page reads METRICS.json on the branch metrics (economics and coordination, docs/setup/metrics.md) and prices the same tokens under an API key, GitHub Copilot's coding agent, unsorry and OpenAI; its price table (PRICES_AS_OF in symphony-panel.js) is kept beside tools/economics.py's and every source is linked at the foot of the page. unsorry (agenticsnz/unsorry) is the closest rival: volunteers' own agents, coordination in Actions.
- The Apps' privacy statement (symphony-start PRIVACY.md, version 9, rendered at /symphony/apps-privacy.html) covers both pages: what they read and write, where the token is kept, that the service keeps nothing and the developer receives nothing.
- The research note docs/research/control-panel.md holds the ask, the design decisions, the cost comparison with its prices and sources, the reviews' findings, what waits on the owner and the follow-ups; it is kept current by the thread that built the pages.
