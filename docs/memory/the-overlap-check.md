The rule requiring an up-to-date branch is off everywhere, and the overlap check says which pull request must bring the default branch in: only one whose change meets what the default branch did since the branch left it.

Under "Require branches to be up to date before merging", every merge made each other open pull request behind, so it brought the default branch in and ran its check again whatever it changed: 127 of the template's first 255 merged pull requests needed such a catch-up and 89 went green, then stale, then ran again (the thread "Stale branch failure statistics"). The owner ordered the rule off on 2026-10-20 for every repository, SymphonyBoard's auto-applied rulesets with it (docs/setup/github.md), so a pull request now merges as it stands and only a conflict stops it.

What the rule guarded, a branch that still merges cleanly but has changed its meaning, is read instead from what each side changed: `python3 tools/locks.py overlap --base origin/<default branch>` (symphony-protocol 0.6.0, docs/agents/PROTOCOL.md, Locks) sets what the default branch changed since the branch's fork, with what that Python code depends on, beside what the branch changes and builds on, and asks for the default branch only where they meet with a write on either side. .github/workflows/ci.yml runs it as the job overlap on every pull request, and .github/workflows/overlap.yml runs tools/overlap.py on every push to the default branch, which judges every open pull request again and writes the check run overlap on its head: success, neutral at advise, failure at enforce. The switch is .github/symphony-locks (off, advise, enforce), at advise; enforce comes with a ruleset requiring the check named overlap and one on the branch locks, both applied by SymphonyBoard, and the claim skill taking locks at the claim.
