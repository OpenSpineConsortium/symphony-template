Publishing part of a repository: .github/symphony/public.json lists what leaves for public repositories; export.yml publishes it by pull request, import.yml takes listed files back.

GitHub sets visibility per repository, so the private repository stays the source and the manifest is the one record of what goes public (the owner's choice of 2026-10-20, "Build it"). tools/public_export.py holds the rules; `bash scripts/check.sh` runs its check, which fails on a listed path that is missing, leaves the repository or matches a `private` glob. export.yml stages each export (a build runs before any token is minted), then pushes symphony/export/<name> in the target with a SymphonyBoard App token for that repository alone and opens or updates one pull request there; import.yml weekly brings the target's versions of an `"import": true` export's listed files back as a pull request here. Each export names its `source`, so a copy of the template exports nothing. Auto-landing in the target was refused by the session's permission check as merging without review: an export pull request lands by the target's own merge rules (symphony-protocol has auto-merge off), so a session merges it once green, on the owner's standing permission. The first export is the lesson notebooks into symphony-protocol's notebooks/. docs/setup/public-export.md says the rest.
