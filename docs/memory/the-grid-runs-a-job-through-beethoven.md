A workflow job can run on the WSU grid through the runner chain that hpcworker's tools/grid_runner.sh serves as Slurm jobs; the connection points from the grid out, and no credential crosses.

.github/workflows/grid.yml runs one command on a compute node, in a checkout of the ref, and keeps the output as the job's log and as an artifact; it runs only while the repository is private and never for a fork's event. The runner is GitHub's own, inside its own image (the runner needs RHEL 8 or later, the grid's nodes are EL7) as a Slurm job on reqp/requeue, registered one job at a time with a just-in-time credential the account's gh mints on the grid into a mode-0600 file that leaves with the job. GitHub's runners cannot reach the grid (the VPN and a one-time code), so nothing is pushed in, and no Claude token goes there: claude.yml, workers.yml and coordinator.yml stay on GitHub's machines. The chain is the owner's to start from the portal's shell; docs/setup/grid.md has each step with its link, hpcworker's docs/OPEN_QUESTIONS.md what the grid has not yet shown, and docs/research/wsu-grid-and-github-actions.md what was measured and weighed, with the second step decided on 2026-10-16: an ssh gate on the grid, through hpcworker, as its own pull request after the runner.
