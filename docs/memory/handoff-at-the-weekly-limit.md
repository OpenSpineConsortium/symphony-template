At 90 percent of an account's weekly window, tools/handoff.py's hooks tell a session once to write the handoff page the next account resumes from (.claude/skills/handoff); the status line and the grid's reading are the only sensors, so a claude.ai cloud session hands off on the person's word.

The status line command (tools/handoff.py statusline, in .claude/settings.json) keeps Claude Code's rate_limits reading in the git directory; on the grid hpcworker's accounts/<N>.use.json and accounts/<N>.handoff-due are read beside CLAUDE_CONFIG_DIR. The hook runs on Stop, UserPromptSubmit and PostToolUse of Bash, says nothing in GitHub Actions, and is switched by SYMPHONY_HANDOFF=off, SYMPHONY_HANDOFF_AT and SYMPHONY_HANDOFF_WINDOW. `handoff.py new` writes docs/checkpoints/<date>/handoff.md, `done` records it (and tells the grid the move may go ahead), and the session-start hook names the newest one of the last 72 hours. A swap of account is near instant for the account and never for the conversation or the prompt cache, which is why the page exists; docs/research/automatic-handoff.md has the readings and the grid answer.
