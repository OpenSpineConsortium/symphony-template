Profiling a session: tools/profile.py reads a session's transcript, the same file tools/usage.py reads for the usage trailer, and gives what the session spent as counts alone, for the research programme under docs/research/beyond-cooperation/.

A Claude Code transcript carries the API's own token counts on every call and every tool call with its answer, so what a session spent on context, tool calls, reading and time can be measured afterwards by code, from the file, with nothing installed and nothing sent anywhere. `python3 tools/profile.py TRANSCRIPT --json FILE` writes the record and prints the report: each API call once by its message id, the context call by call with its cached share and compactions, calls by tool with their failures, bytes and seconds, reads and re-reads of files, and seconds in tools (two at once counted once) against seconds outside them, the model's and the harness's. The record never carries a path, a command, a prompt or any text, so it can be committed beside the question it answers; tests/test_profile.py is the definition of every count.

The programme measures a way of working before changing it: context compression, fewer tool calls and less code reading are its arms, each read beside whether the work landed, and no run that spends tokens starts without the owner's word and the number. The first record is docs/research/beyond-cooperation/baseline-2026-10-15.json, the thread that wrote the instrument, taken from a transcript that is not kept, so the tests are its reproducible part; its first API call carried 120,867 tokens before any work: 43,468 read from a cache shared with sessions of its kind (the harness's prompt and its tools' schemas) and 77,397 written for the session, the project's instructions (about 18,000 tokens) and the thread's own start, carried by every later call at the cache-read price.
