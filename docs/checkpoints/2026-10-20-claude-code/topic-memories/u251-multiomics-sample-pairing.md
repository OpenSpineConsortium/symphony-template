Verified 2026-09-27 against the live GEO record, not assumed:

- **Ten of ten** GEO Series carrying both a methylation-array and a sequencing assay type are **SuperSeries**
  (Entrez `gds`, both `[DataSet Type]` terms + `gse[Entry Type]`; each has `!Series_relation = SuperSeries of:`).
  So arrays cannot be added to GSE338105 -- the methylation data goes in its own Series, joined by a SuperSeries.
- **GEO mints a BioSample for a sequencing sample and none for an array sample.** In GSE335256 the sequencing
  SubSeries carries one `!Sample_relation = BioSample:` per sample and the array SubSeries carries zero. So a
  SuperSeries links the two *Series* and **nothing at NCBI links the two samples** -- there is no shared accession to
  join on. Multi-omics sample pairing exists only in metadata the submitter writes.

**Three pieces of tissue carry two names**, because the array core and the sequencing core named the animals
differently. RNA side (GSE338105, SRA, FASTQ names) -> array side (the chip, the core's sheet, every analysis in the
repo): **NL70B = IL70B, NL71B = IL71B, N269B = N2**. The other five (IL66B, IL67B, IL68B, IL69B, C2B) match. IL64B and
N168B have no array. `IL` is the *laboratory's own* prefix (its RNA key says IL-70/IL-71, and IL is its MRI prefix);
`NL` appears only in the sequencing core's file names, so the **public** record carries the odd label -- and it is the
one that cannot be changed.

**Why:** Greg's directive 2026-09-27 was to rename nothing and instead make the correspondence unmissable, because
the RNA names are public and minted in SRA while the array names are what the chip and all analyses use.

**How to apply:** never pair the two assays by name. Use `GEO/multiomics_sample_key.tsv`, generated by
`GEO/make_sample_key.py`, which cross-checks the array sheet against the accession map both ways and refuses to write
if they disagree. The deposit states the pairing four times: sample title, five characteristics fields, Series
summary, and that key as a supplementary file. See [[u251-name-sweep-traps]] and [[u251-project-containment]].
