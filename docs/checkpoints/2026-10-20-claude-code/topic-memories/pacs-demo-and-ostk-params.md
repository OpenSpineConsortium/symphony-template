**OpenSpineToolkit `ostk`** (repo RENAMED from OpenSpineToolbox, 2026-06; GitHub
`Gregory-Schwing-MD-PhD/OpenSpineToolkit`; fresh local clone at
`C:\Users\grego\OneDrive\Desktop\OpenSpineToolkit` -- the old `OpenSpineToolbox`
folder is stale/VS-Code-locked, delete when convenient). Implements Greenberg Ch.73
spinopelvic params from v3 (Vert+S1+femur): PI/SS/PT, LL (+per-segment), PI-LL
mismatch (+`ll_target_deg`), SRS-Schwab modifiers + Eq.73.1 LL-increase, Roussouly
type (by SS) + PI band, `cobb_angle`, and `spinopelvic_summary_from_label` (one call).
PI/PT hip axis uses `femoral_head_center` -- a ROBUST acetabular-interface sphere fit
(seed = femur voxels touching `left_hip`/`right_hip`, then extend through the neck by
shell-refit), NOT the old superior-slab fit which biased the center into the
neck/trochanter (radius now ~22mm not ~29mm).

**PACS demo** lives in a *different* repo: `openspineconsortium.github.io/pacs/`
(NiiVue viewer; left-click localizes crosshair, left-drag=zoom, right-drag=pan,
scroll/1-finger=slice, pinch=zoom/pan via a CSS transform on BOTH gl+overlay so they
move as one unit; iPhone layout = pinned viewer + grouped-card controls). Data-driven
by `pacs/data/<case>/metrics.json`, generated by
`OpenSpineToolkit/tools/export_demo_case.py`. Bundled case = **0003** (v3, full
PI/SS/PT/LL). Cache-bust query bumped on every pacs.js/pacs.css change.

**Why:** demo of the parameter code for the consortium site + papers.
**How to apply:** re-run `export_demo_case.py --geometry-only` then bump the cache-bust.
Do NOT reintroduce supine-CT / standing-XR framing or "SVA/TPA out of scope (needs
C7/T1)" -- user removed it because some scans DO include C7/T1, so the blanket claim is
wrong. Pushing github.io publishes publicly.
